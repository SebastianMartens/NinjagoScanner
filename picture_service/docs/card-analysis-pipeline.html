picture_service · AI Analysis

From a card photo to judged card details

The goal is to turn one stored photo of a Ninjago trading card into the Judged section of its sidecar: the series, card number, card name and language, plus an Analysis Status that says whether that worked.

The AI model only reads what is visible. It never decides which catalog card a photo is. Two model calls extract and interpret attributes, then a deterministic scorer compares them with the real catalog and picks the card. That keeps the final answer tied to cards that exist in CatalogService, and makes it reproducible for a given set of attributes.

Stage 1 · LLM vision

Detect attributes

In
The photo and its file name (for the image MIME type). No catalog, so the model cannot guess toward a known card.
Does
Asks the vision model to report what it sees for a fixed list: vehicle, trap and action tags, defense/tempo/attack/power values, text box, card name, card number, shiny finish, puzzle-piece, and whether any card is visible at all.
Out
A flat map of scalar values. Nested values and nulls are dropped.
Fails
Model API error, empty reply, or invalid JSON. The result is failed and the raw reply is kept.
Stage 2 · LLM text

Derive attributes

In
Only stage 1's map, written out as key: value lines. The model does not see the photo again.
Does
Reasons over the values: sets a coarse class (character, action, vehicle, trap, puzzle-piece, limited edition, art), copies card number and name, adds an English name for German or Polish cards, and guesses the language.
Out
A second flat map. A class outside the allowed set is removed.
Fails
Same as stage 1. The stage 1 attributes stay on the failed result.
Stage 3 · deterministic

Match against the catalog

In
Stage 2's map and the catalog snapshot loaded from CatalogService. Stage 1's raw attributes are not used.
Does
Scores every catalog card in every series. No series is guessed first. The best card's series becomes the resolved series.
Out
Series, card number, catalog card name, language, and status ok.
Fails
No card reaches 50 points, or the top score is shared by different series/number pairs. The result is failed with "Keine passende Karte gefunden."

How stage 3 scores one catalog card (max 100)

SignalPointsRule
Card number50Equal after normalizing (007, 7, 7.0 are card 7). Earns nothing if both sides have a class and the classes differ, because then the number or the class is probably misread.
Class20The derived class equals the catalog card's class.
Card name0 – 30Exact normalized match gives 30. A similar name gives 30 scaled by similarity, nothing below 0.6. Cards in another language are also compared by the English name from stage 2, and the better similarity counts.
Threshold≥ 50A number alone is enough. Class plus exact name is enough. Class plus a partial name is not. The winner must be the single best candidate; the same series and number listed under two categories counts as one card.

Stage 3 always returns ok for a resolved match. The code does not yet set uncertain here.
